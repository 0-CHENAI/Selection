# Word 原文绑定与检查结果复用

日期：2026-11-06。实施前检查点：`77acaa6d3`（test，本地提交，未推送）。

## 修改

- 准备阶段支持 `content_mode=verbatim` 与原始 `source_text_path`，生成 `preparation_id` 并把原文路径、SHA-256、模板版本及工作区写入会话 data。新写、摘要和明确重排使用 `authored`。
- 同一用户请求内，写入重试即使漏传原文或 preparation_id，也继承当前准备记录。旧式写入阶段才提供原文的调用也会先持久绑定再验证计划，失败重试不能跳过。记录损坏或原文变化明确报错，不按“未绑定”处理。
- 默认准备记录按用户请求隔离，内部自动重试沿用同一请求。新的用户请求可以正常修改已有文档，不会永久受到上一次原样转换约束；显式使用旧 preparation_id 继续任务时，重新绑定到本次请求并保留检查。
- 成功返回 `verified` / `unverified`、段落数、表格行/单元格数、原文覆盖和顺序、成品 SHA-256。未做事实或视觉验收会明确标出，不作为默认待办。
- 相同编辑计划、原文版本、模板版本与未变化的成品复用保存结果，返回 `reused=true`；不重写文件或重复结构检查。JSON 对象键顺序不影响匹配，数组顺序仍然有效。变更后的文件不能借用旧结果；外部编辑通过新检查后，旧写入结果失效。
- 当前生成请求内，外部编辑若丢失绑定原文会被交付守卫阻止。新用户请求的已有文件定点修改不强加旧原文逐字要求，仍保持原有版式守卫。
- 原文允许来自工作区或本会话 dataFolderPath，输出仍限定工作区。错误明确标出 `source_text_path` 或 `output_path`，避免修错字段和无必要复制。

本次未增加工具调用硬上限，也未拦截成功后的全部 CLI 调用。未实现通用的增量编辑计划协议或旧会话提示词版本迁移。
