# 任务可靠性、反馈闭环与协作：人工测试清单

用途：实现完成后的集中人工测试，不作为功能已完成或已经验收的声明。自动回归保留核心协议、持久化、权限和覆盖保护；人工按下面的真实使用路径验证，无需穷举所有组合。

测试前记录应用版本/提交、系统、模型连接和工作区位置。使用可丢弃的项目及文件；重启恢复测试先保存当前工作。

## P0：可靠性

| 使用路径 | 预期结果 |
| --- | --- |
| 发起包含多次工具调用的长任务，中途手动整理上下文 | 过程与预览连续；整理结束继续原任务；已有结果保留；已执行写入不重复执行；超限时有明确恢复入口。 |
| 输入一段本身超出模型容量的内容，再使用选择模型/新会话草稿入口 | 原文与附件不静默删减；不一直重试；新草稿保存成功后才跳转，且不会自动发送。 |
| 只读任务执行中强制退出应用后重启，再做一次有文件写入的任务 | 能核对的进度继续；已取消任务不复活；无法确认的 Shell/外部写入暂停并说明原因；新的操作仍遵守当前权限。 |
| 在 Windows 11 跨盘及含中文/空格的位置生成文件；移动文件后点击原成果入口并重新定位 | 打开准确文件；失败提示留在成果行；重新定位是明确操作；不同内容不会被静默当作原版本；macOS 和远程工作区分别选一例核对主机。 |

## P1：反馈闭环

| 使用路径 | 预期结果 |
| --- | --- |
| 选中正文、代码或文本成果的一段提出修改，期间关闭弹层/切换详情/重启 | 目标和原选区准确；未发送草稿保留；发送不重复创建请求；处理结果能从原入口追踪。 |
| 修改期间在编辑器里改动原文件或正文，再等待候选应用 | 停止覆盖并显示冲突；旧内容、用户修改和候选均保留；过期选区要求重选。 |
| 对 Office、PDF、图片提出一次文件级修改 | 实际生成可打开的新文件；可以切换旧/新预览；验证文案明确区分格式检查与内容判断，不显示虚假的元素级差异。 |
| 查看文本差异、恢复旧版、再次反馈，随后重启 | 恢复创建新版本；版本链和反馈关联一致；“已交付/已更新”不等于“用户已确认”；显式清理不删除仍被使用的版本。 |

## P2：协作

| 使用路径 | 预期结果 |
| --- | --- |
| Git 项目保留未提交/未跟踪文件，启动两个写入子任务；另选非 Git 项目重复一次 | 默认独立环境，原工作区不被清理；子任务候选路径不被误称为最终成果；独立节点可继续。 |
| 两个 Agent 修改同一文本文件，再修改同一二进制文件 | 无冲突文本通过验证后集成；冲突可查看具体文件和候选；二进制要求选择或修复，不自动合并内容。 |
| 集成期间手动编辑目标文件，或强制退出后重启；再反馈修改上游成果 | 不覆盖用户编辑、不重复集成；未完成事务先恢复/回滚；只使有关依赖失效，无关结果保留。 |
| 子任务失败或取消，查看主会话、子会话和协作详情 | 执行结束、验证和集成状态一致；失败影响范围明确；无法限制写入范围的任意命令不会偷偷进入并行写入。 |

## 跨阶段交互抽查

选一个旧会话及一个新会话，抽查重新加载/重连、导出导入、子会话预览和 viewer。旧正文、批注与链接应保留。用键盘打开详情、按 Escape 逐层关闭并确认焦点返回入口；再用窄窗口和另一主题抽查一次。关闭窗口不停止后台任务，需要停止时使用明确的停止操作。

出现问题时记录：系统、提交、任务标题/标识、发生时间、操作步骤、预期/实际结果及报错截图。提供脱敏的必要日志即可，不需要完整私人正文。
