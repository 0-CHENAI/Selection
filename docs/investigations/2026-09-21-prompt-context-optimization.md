# Prompt 上下文优化与验证

## 范围与回滚边界

优化基线为 `0ad04d4a`。之前的修改已单独保存：

- `91868827`：会话隔离、成果文件及参考来源展示。
- `53a4f248`：自动压缩、摘要恢复、无效工具重试限制。
- `0ad04d4a`：自然写作技能及成功读取状态。

本轮在 `codex/prompt-context-optimization` 修改；没有推送。

## 问题、原因、修改方式

| 问题 | 原因 | 修改方式 |
| --- | --- | --- |
| “技能”显示约 12.9K，看起来异常膨胀 | 正文提及的 `<available_skills>` 被当成目录开始，直到真实目录闭合才结束 | 按独立标签块识别，并忽略代码围栏中的例子；工具结果和助手回复归入消息 |
| 浏览器和预览说明长期占上下文 | 常驻完整 JSON 示例、命令列表、多个重复预览流程 | 保留能力入口、关键约束和手册路径；详细格式按需读取；预览手册新增短 quick start |
| 重复工具定义消耗 Token | 规范工具名和五个历史短名均发送给模型 | 请求层仅发送规范名称；执行注册表保留旧别名；统计使用同一过滤函数 |
| Swarm 关闭仍可能自行派生 | 后面的通用“长任务/隔离上下文可 spawn”与开关规则冲突 | 删除这组替代资格，只应用当前会话的 Swarm 规则 |
| 格式指令易受通用 Markdown 建议干扰 | 通用排版建议未明确让位于用户输出格式 | 明确用户指定格式/schema 优先，机器可读输出不加包装或解释 |

统计修正本身不节省 Token。当前本机技能目录估算约 2,565 Token；技能正文经读取后计入对话消息。分类仍是估算，不是供应商 tokenizer 的精确值。

## 固定输入测量

运行：

```sh
bun scripts/evals/prompt-context-eval.ts
```

使用同一虚拟工作区 `/evaluation/workspace`，关闭 Swarm、关闭工具 metadata 文案、不附用户偏好或项目内容。工具项是 session tool factory 的 JSON 估算，实际请求还会受功能开关、工具过滤、模型提示和供应商封装影响。

| 项目 | 优化前估算 Token | 优化后估算 Token | 减少 |
| --- | ---: | ---: | ---: |
| 基础系统提示词 | 11,295 | 7,466 | 3,829（33.9%） |
| Session 工具定义工厂 | 12,834 | 10,198 | 2,636（20.5%） |
| 上述两项合计 | 24,129 | 17,664 | 6,465（26.8%） |

使用真实本机工作区路径，系统提示词为 7,493 Token；路径长度造成小幅差异。没有为追求原先 6–7K 的目标进一步裁掉业务合同。

首次使用预览/表格等功能会增加手册读取成本，不能把上述固定输入减少量当成每个任务的净节省或费用降幅。稳定系统前缀仍可缓存，但缓存命中不等于不占上下文窗口。

## 保留的核心规则

- Office router、专用格式技能、交付校验机制及文档转换优先级。
- 精确的工作目录、session data/plans 目录、临时产物隔离及用户显式交付位置。
- 搜索引用、来源真实性、避免普通会话重复输出参考列表。
- 自然写作技能按交付意图加载，代码/普通问答不自动读取，保留原文与用户风格优先。
- 权限模式与任务面板的用户控制权。
- Swarm qualification、结构化 verdict、汇总和背景任务生命周期。
- 压缩算法、80% 触发阈值、实际 usage 数据和输出预算策略；本轮不改变这些策略。

不引入新的分类模型、关键词路由、工具搜索，也不截断工具参数 schema 或用户技能描述。

## 验证与局限

定向验证包括真实 Pi Agent 对旧别名的执行、实际 provider 请求及溢出重试的 schema 去重、上下文统计、技能读取、自然写作、权限/Office/Swarm 提示规则和翻译键一致性。Electron / shared / Pi 类型检查以及 Pi 构建通过。

真实模型对照使用已配置的 Laufry 与 Opus，各对新旧提示词测试 30 个合成策略场景、重复 3 次。场景按每次请求打包，问题判断与精确 JSON 格式分开统计。脚本不会执行任何代理工具或发送用户会话内容。

```sh
bun scripts/evals/prompt-context-eval.ts --live --models=Laufry,Opus --out=/tmp/prompt-context-eval.json
```

最终固定场景对照结果（[原始结果](../qa/2026-09-21-prompt-context-eval.json)）：

| 指标 | 原提示词 | 新提示词 |
| --- | ---: | ---: |
| 策略判断正确 | 180 / 180 | 180 / 180 |
| 严格裸 JSON 字符串数组 | 2 / 6 请求 | 3 / 6 请求 |

其余格式偏差主要为额外 JSON 代码围栏或带 id/choice 的对象数组；不把这些包装差异误计为策略错误，也不忽略它们。一次旧提示词请求超时，定点重试完成；原失败记录保留。不能凭这点样本宣称总体质量提升或输出格式问题已经根治。

本轮最终定向测试 492 项通过。分类器还用约 7.5K 系统提示词加 200K 字符工具结果做了 100 次本机估算：平均约 2.4ms/次；这不是跨平台性能承诺。

这只能验证策略理解，不能证明完整工具调用链、长任务、Office 成品质量或真实写作质量完全不退化；亦不能把批量场景视为相互独立的统计样本。没有宣称完成端到端质量认证。

## 研究依据

- [Anthropic：Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)：保留高价值指令和工具入口，按需获得具体上下文。
- [Agent Skills overview](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview)：目录与完整操作知识分层加载。
- [Tool use with prompt caching](https://platform.claude.com/docs/en/agents-and-tools/tool-use/tool-use-with-prompt-caching)：稳定工具/系统前缀有利于缓存，不能据此忽略上下文占用。

这些原则用于本仓库多供应商架构；没有直接引入供应商专属工具搜索或修改底层压缩算法。
