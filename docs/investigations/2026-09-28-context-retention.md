# 分层上下文保留

实现遵循 [Ponytail](https://github.com/DietrichGebert/ponytail/blob/main/AGENTS.md)：复用 Pi 摘要、原生日志与既有 session-info 通道，不增加数据库、依赖、预测模型或每次工具调用后的额外模型请求。

| 环节 | 实际行为 |
| --- | --- |
| 自动状态维护 | 每次请求从当前分支持久日志重建最新用户要求、失败操作与最近成功操作。同一操作的成功重试才能自动消除其旧失败；成功返回不等于任务验收。 |
| 语义整理 | 复用已有压缩调用，在普通摘要后生成结构化任务更新；自动合并目标、约束、决策、待办和进度。用户改口复用原 key，跨 key 冲突由模型显式解决。无需主动调用 task_context 才能记录；该工具仍供提前记录使用。 |
| 来源核对 | 更新必须引用当前分支的真实消息与原文。目标和约束只能引用用户正文；运行上下文不能成为用户授权来源。旧来源不能覆盖新来源，失败工具或助手自述不能将待办标成已解决。 |
| 压缩保护 | 不允许缺少更新的旧要点被默默删除；对摘要补入确定性恢复状态。无效或缺失更新会保留旧要点与原始事件并明确标注待核对。没有可用摘要正文、截断、取消或失败则沿用原有拒绝机制。 |
| 提交时机 | 模型生成的任务更新先写入原生日志的暂存事件，由成功写入的 SDK checkpoint 引用后才生效；不依赖压缩结束回调，避免中断后摘要与要点不同步。split-turn 两段共享暂存状态，失败留下的暂存事件不生效。 |
| 优先保留 | 有界恢复上下文优先携带有效约束、未完成事项、未消除的工具错误、完成操作证据及决策；另外保留首条和近期用户原文片段。遗漏有计数与回查入口。 |
| 原文回查 | session_history 按消息 ID、关键词与分页回查，包含原始工具调用参数；不读取兄弟分支。用户正文位置元数据不改变原始消息。图片/音频仍只返回文本部分。 |
| 工具结果整理 | 仅当本次请求提供 session_history 时，缩减早于当前用户轮、最近八条结果之外、可从日志精确恢复的成功纯文本 read/grep/find/ls/bash/web_fetch/web_search 结果。保留首尾与消息 ID，不改磁盘记录或调用配对；错误及多模态结果保留。 |
| Swarm 恢复 | 正常模型请求前通过现有 get_session_info 通道获取当前调度状态、子任务结果 ID 与待汇总合同；不从摘要猜状态。查询有超时和取消处理，失败显式标成未知。子任务 completed 不会消除父级 pendingAggregation。 |
| 动态预算 | 80% 是默认上限；根据固定提示占用、输出预算与最近三条工具结果高水位提前留出余量，最早不低于有效窗口的 50%。无可压缩历史时仍遵循原来的软阈值和物理上限保护。 |

预算：请求注入最多 6,000 字符并随小窗口缩小；任务记录最多 24 条、12,000 字符，超限拒绝并保留原数据。调度状态与来源片段超预算时显式标注省略。历史 provider usage 仍作为保守上限；SDK 自身也可按原始消息先触发压缩。

用户正文位置元数据由新请求写入，旧日志没有该元数据时沿用原消息。语义整理在压缩时发生；压缩之前的新要求和工具结果由原始事件即时恢复，不为每一条消息额外调用模型。

验证涵盖真实 Pi SDK 连续五次压缩、自动记录、用户改口、错误重试、来源伪造拒绝、完整原文回查、分支隔离、会话重开、动态预算、最新调度状态覆盖及 checkpoint 写入失败不提交暂存更新。模型响应使用离线 provider，尚未完成真实模型长任务 A/B 或生产 UI 验收；来源与状态校验不能证明模型对自然语言的理解一定正确。

本轮定向验证：118 项测试通过；Pi 与 server-core 类型检查、Pi 构建、修改的共享代码 ESLint 和 git diff --check 通过。

## 代码与业务逻辑复审

- 错误关闭记录必须保持 pending 类型；仅接受较晚的用户正文指示或相同工具、相同参数的成功重试。历史中不满足此条件的记录也不能隐藏错误。
- 所有用户来源的记录均排除注入的运行上下文；同一 key 不允许改变类型绕过验证。
- 用户正文元数据按日志顺序匹配并消费一次，支持零偏移，避免相同文本的新旧消息相互污染。
- 任务快照先暂存，再由检查点引用提交；失败的压缩不会改变有效任务状态，已提交记录不依赖结束回调恢复。
- 来源包截断优先保留最新证据；摘要元数据从最后一个标记解析，避免正文中引用标记干扰解析。
