# 会话卡住：执行链审查与故障注入

## 范围与结论

本次是 #360 的后续全链审查。#366 的单次模型流时限只覆盖 provider 流不结束，不能覆盖启动、工具桥接、清理或客户端状态竞争。以下原因来自真实代码路径与故障注入；不把它们冒充历史截图的唯一根因。

| 环节 | 排查结果 / 修改 |
| --- | --- |
| 用户发送 → RPC 确认 | 已检查持久化后 ACK、失败反馈、普通 RPC 请求超时；维持确认合同，不自动重发已确认任务。 |
| 会话初始化 | 原初始化无取消/总时限，晚到结果可能给已停止任务挂载运行实例。增加初始化时限、取消及代次复核；初始化失败回收已创建资源。 |
| Pi 凭据与启动 | 原 ready Promise 只有 resolve，子进程提前退出或一直无 ready 会永久等；并发初始化可能重复 spawn。串行共享启动承诺，失败/超时/停止可拒绝，凭据晚到后禁止 spawn。 |
| JSONL 进程链 | 原先只关注进程 exit；stdout 已关闭、stdin 写失败或异步桥接处理异常可能没有终止消费者。加入管道错误收束，旧进程回调必须验证实例身份，避免清空新进程。 |
| 模型流 | 复用 #366 的调用边界、底层取消、部分内容与用量保留；长生成与连接静默不混同为无进展。 |
| 权限 / 代理工具 | 原 abort 先等 SDK，而 SDK 等待的工具桥接在 abort 后才释放，形成循环等待；代理工具结果还没有统一释放。先释放两类桥接，再等待 SDK；中断结果明确可能未知，不自动重试。 |
| 压缩 / 重试 | 原压缩等待超时后直接继续请求，可能并发。改为明确失败；认证重试在排队开始和异步销毁后都复核停止、代次、答案提交身份。 |
| 结束 / 清理 | 事件 sink 抛错、MCP/浏览器清理无返回、未读状态写入失败可能阻断完成通知。隔离投递与非关键元数据失败，为清理提供等待边界。关闭未确认会记录失败；要求确实停止的删除路径继续保留资源目录。 |
| 客户端恢复 | 迟到的历史快照可能覆盖已收到的完成/新轮消息，使 UI 回到运行状态。加载前后比较本地状态身份，仅应用仍有效的快照。 |
| Swarm / DAG | 保留既有独立子任务停止合同；通过共享完成通知链解除清理阻塞，不跳过聚合或验收。 |

## 验证证据

- 真实子进程注入：提前退出、无 ready、stdout 关闭但进程存活、停止时凭据未返回、旧进程迟到退出、失败后的新请求成功。
- 真实打包 Pi + SDK + 本地 HTTP 模型：分别停在权限答复和代理工具结果等待，发送 abort，均收到 agent_end。
- 会话生命周期：事件 sink 故障仍通知 Conductor；认证重试与停止交错不会复活；初始化过期结果不能挂载；运行时清理不返回也能结束等待。
- 客户端：迟到快照与完成事件/新回合交错；保留历史消息同时修正运行状态。
- 复用已有模型流、源切换、重新生成、持久化、RPC、重连及 renderer 事件回归。

## 边界

这些修复不会依据固定等待时间宣判“模型没有进展”，也不会自动重复业务操作。时间上限用于初始化、调用或清理的资源保护。

外部业务工具已启动但结果未知时，取消等待不代表外部操作已撤销；日志与中断信息不能宣称它已成功或失败。真正同步阻塞主进程事件循环、操作系统挂起等情况无法靠同一进程的 JS 计时器强制修复，仍需独立进程监管/运行态剖析。本次没有声称复现所有历史卡顿，也没有把单测等同于 Windows 实机产品验收。
