# #297 超时与失败节点恢复复审

## 确认范围

- 精确英文报错不在 Selection/Pi 已安装源码中；不能据约 10 秒的症状断言客户端有固定超时。
- 本地 HTTP 200 SSE 服务延迟 10.1 秒发送首 token，当前 Pi OpenAI-compatible SDK 成功收取结果。没有调用真实模型。
- 没有扩大超时或无限重试；显式 retry.limit 与用户 backoff 继续生效。

## 修改和复审修正

- provider_timeout 独立分类，中文及其他语言提示；节点完成事件传递安全错误码，日志和重试提示不再只剩 error。
- 瞬时网络/服务/超时/流中断错误未配置退避时采用 1 秒起步的有限指数退避。
- 修正 retry-wait 被误判为运行已结束、从而取消定时器的问题。
- 普通 session DAG 提供失败节点重试入口，保留完成输出、累计 token、节点历史尝试数和预算边界。
- 复杂控制节点不暴露部分重试入口；服务端同样拒绝，避免错误恢复循环、审批或动态展开状态。
- 恢复请求使用单条持久化日志记录节点集合，避免中途崩溃导致半恢复；支持进程重启后继续。
- SSE 诊断只记录状态、受限请求 ID、阶段及耗时，保持原始字节及取消语义；日志失败不影响模型输出。
- agent_settled 作为生命周期通知忽略，不重复终止，也不再警告未知事件。

## 验收边界

原始 Windows / Laufry 上游错误尚未实机复现，不能声称上游超时根因已消除。首字节可能是心跳，不等于首 token，日志使用 first-bytes 准确区分。手动失败节点重试会重新执行失败节点，因此应检查其已有结果；不会重跑成功依赖。复杂 DAG 部分恢复仍不支持。
