# Issue #330 正文交付修复

## 协议

普通用户会话使用 `explicit-v1`：模型通过 `submit_answer({ markdown })` 提交完整、独立的 Markdown。过程文本保留在工作链，provider 的 `final` 标记不再直接表示正式答案已经交付。

第一版不引用或拼接旧片段；验证推翻前文时，由模型提交修正后的完整答案。短回复、澄清问题和拒绝回答允许直接提交。结构校验不保证答案的语义完整性。

消息保存 `answerProtocol`、`answerRunId`、`answerCommitted`；用户消息另外保存 `answerRecoveryAttempted`。字段缺失的历史回合保留原有展示。隐藏的续跑沿用原任务身份，独立后台唤醒则建立新的交付回合。

## 执行与持久化

- session tool 注册表提供工具定义、参数校验和 Explore 模式许可。实际启用的 Pi backend 在主进程调用服务端交付入口；子进程只提供 SDK 身份和执行请求，不能自行宣告交付成功。
- 接受前校验活跃回合、重复/并发提交、前台工具、Swarm worker 与聚合合同。SDK 同批工具数不是 1 时禁止提交答案。
- 正文及分支锚点先保存，再回读确认消息确实落盘，随后发布正式正文事件。成功回执不重复完整正文，工作链不保存提交工具的原始 Markdown 参数。
- 成功提交后，执行检查阻止后续工具；SDK 保存工具结果后终止本轮，并把分支锚点更新到包含完整回执的日志条目。
- 自然完成但漏交付时，最多增加一次同模型、同上下文的隐藏收口。收口只暴露并允许 `submit_answer`，调用量计入原回合。
- 取消、失败、计划/认证交接、等待 Swarm worker 不触发收口。收口仍失败时保留工作内容并报告“未完成答案交付”。重启不自动调用模型。
- 内部 worker、Conductor 和非普通 system prompt 会话不启用此协议。

## 展示合同

正式卡片只使用已提交的正文，不用更长的流式草稿替换它。复制、Markdown 预览和弹出阅读复用这份正文。重复回执或迟到文本不会覆盖或降级正式答案；新交付回合不会被上一轮的去重规则隐藏。

## 验证记录（2026-09-10）

最终验证：23 个测试文件共 328 项通过；`typecheck:all`、仓库 lint（仅既有 warnings）、Pi 构建、服务端构建及 Web UI 类型检查通过。viewer 在命令行启用 ES2023 库后通过。

新增测试覆盖 SDK 批次限制、主进程桥接、服务端交付/收口、持久化和锚点、renderer 消息身份、正式正文归组及历史兼容；同时运行原有 phase/intermediate/grouping、空回复、Swarm 和用量回归。

实际使用本机配置的兼容 API 连接 `Laufry`，在临时工作区执行蒙提霍尔解释与 10,000 次模拟。模型成功提交 3401 字符正文，包含完整规则、编号讲解、概率表和模拟结果，无须自动收口。正式消息和 SDK 工具结果锚点均已回读确认。模拟中发生过脚本运行错误并由模型修正，最终正常交付。

将该会话的实际持久化数据载入现有 TurnCard 后，确认完整讲解及 3 张表格显示，折叠工作链后正文仍在。验收期间用户接管浏览器，因此实际复制和 Markdown 按钮点击未完成确认；相关正文传递与消息一致性由自动化测试覆盖。

本机没有第二个带明确 phase 的独立 provider 配置，该类型仅完成事件回归，尚未真实模型验收。

独立 viewer 类型检查存在基线问题：配置只启用 ES2021 库，而已有共享组件使用 `Array.findLast`/`Array.at`。不修改该既存配置；另外用命令行 `--lib ES2023,DOM,DOM.Iterable` 检查本次变更的查看器兼容性。

验收预览使用 renderer 下的 `issue330-preview.html`、`issue330-preview.tsx` 和 `issue330-preview-data.json`。由于用户已接管浏览器，临时预览及其开发服务器保留，未加入生产构建入口。

## 提交前审查修复

- 阻止停止处理后的历史回退逻辑将新协议的未交付过程文本提升为正式答案；旧回合保持原行为。
- 在答案和收口状态的持久化等待之后重新校验取消及回合身份，防止取消后发布正文或发起收口；回滚仅恢复仍属于本次答案的最后回复元数据。
- 补齐 JSON Schema 工具列表的协议开关传递，确保调用方关闭答案工具时真正隐藏它。
- 忽略已交付回合的迟到文本增量和完成事件，同时保留后续回合正在生成的内容。
- 补齐无起始事件的工具结果及中断流式文字的持久化协议身份。

前三个生命周期缺陷有先失败、修复后通过的回归证据。审查修复后运行同一组 23 个测试文件；真实模型及浏览器记录沿用上述验收，本次未重新接管用户浏览器。
