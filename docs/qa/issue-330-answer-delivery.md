## 重新生成交付冲突修复（2026-09-15）

### 问题与根因

本机会话的两次重新生成共发生 9 次 `submit_answer` 调用，均返回 `Answer could not be persisted`。重新生成事务在结束前始终持久化旧消息，而正式交付又要求新答案先落盘再发布，两者形成循环依赖。最终通用错误将系统保存失败描述成模型未提交正文。

### 修复与业务审查

- 生成过程中继续保存旧消息和旧 SDK 身份；只有完整答案通过业务约束后才标记提交候选，将新消息及新 SDK 身份一起写入既有会话快照。回读成功后同步提交重新生成事务，再发布正式答案。
- 保存失败时清除候选并刷新回滚快照；取消仍保留旧答案和原 SDK 上下文。已经持久化并发布的答案不会因为迟到的停止信号被恢复成旧答案。
- 回滚快照改为深拷贝，防止重新生成对用户消息 `answerRunId`、`answerRecoveryAttempted` 等字段的修改污染旧历史。
- 系统保存失败使用独立提示，禁止本轮再次接受答案提交，并跳过无效的隐藏模型收口；模型漏提交仍保留最多一次自动收口。前台工具、Swarm worker、聚合合同、并发提交等既有校验保持有效。
- 界面事件发送失败只记录诊断，不能撤销已保存的正式答案；重载仍可恢复正文。
- 持久化写入移除替换前的删除操作，直接重命名替换目标；故障注入确认替换失败时旧会话文件仍在。

### 验证与边界

新增 8 项回归，覆盖直接交付与隐藏收口的重新生成、真实磁盘回读、保存失败分类与停止重试、取消与回读失败回滚、快照隔离、连续重新生成、迟到停止、SDK 锚点、界面事件失败及文件替换失败。最初新增的 3 项交付回归在修复前失败、修复后通过。

最终使用绝对文件路径执行相关测试，避免 Bun 的路径过滤同时匹配 `dist/server` 中的构建副本：47 个文件、388 项通过、0 失败。`typecheck:all`、仓库 lint 与服务端构建通过；lint 有既有 warnings，修改持久化代码后再次运行 shared lint 通过。

本次使用模拟 agent 驱动真实 SessionManager 与文件系统，包含 `regenerateLastResponse` 实际入口和 renderer 状态回归；未重新调用真实模型、操作已安装客户端或进行 Windows 实机验收。没有修改已有用户会话，也没有将服务端构建等同于已安装客户端更新。

## 协议

普通用户会话使用 `explicit-v1`：模型通过 `submit_answer({ markdown })` 提交完整、独立的 Markdown。过程文本保留在工作链，provider 的 `final` 标记不再直接表示正式答案已经交付。

第一版不引用或拼接旧片段；验证推翻前文时，由模型提交修正后的完整答案。短回复、澄清问题和拒绝回答允许直接提交。结构校验不保证答案的语义完整性。

消息保存 `answerProtocol`、`answerRunId`、`answerCommitted`；用户消息另外保存 `answerRecoveryAttempted`。字段缺失的历史回合保留原有展示。隐藏的续跑沿用原任务身份，独立后台唤醒则建立新的交付回合。

## 执行与持久化

- session tool 注册表提供工具定义、参数校验和 Explore 模式许可。实际启用的 Pi backend 在主进程调用服务端交付入口；子进程只提供 SDK 身份和执行请求，不能自行宣告交付成功。
- 接受前校验活跃回合、重复/并发提交、前台工具、Swarm worker 与聚合合同。SDK 同批工具数不是 1 时禁止提交答案。
- 正文及分支锚点先保存，再回读确认消息确实落盘，随后发布正式正文事件。成功回执不重复完整正文，工作链不保存提交工具的原始 Markdown 参数。
- 成功提交后，执行检查阻止后续工具；SDK 保存工具结果后终止本轮，并把分支锚点更新到包含完整回执的日志条目。
- 自然完成但漏交付时，最多增加一次同模型、同上下文的隐藏收口。收口只暴露并允许 `submit_answer`，调用量计入原回合。
- 取消、失败、计划/认证交接、等待 Swarm worker 不触发收口。收口仍失败时保留工作内容并报告“未完成答案交付”。重启不自动调用模型。
- 内部 worker、Conductor 和非普通 system prompt 会话不启用此协议。

## 展示合同

正式卡片只使用已提交的正文，不用更长的流式草稿替换它。复制、Markdown 预览和弹出阅读复用这份正文。重复回执或迟到文本不会覆盖或降级正式答案；新交付回合不会被上一轮的去重规则隐藏。
