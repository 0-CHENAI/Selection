# 长会话虚拟列表

2026-10-12，使用实际 ChatPage / ChatDisplay 和 120 轮固定长对话验收；不调用模型。

## 问题与修改

原来的渲染分页在向上滚动时挂载一批完整回复。即使限制分页数量，长 Markdown、代码和工具卡片仍在同一次提交中解析和布局。本机 Codex 前端的只读检查显示其使用可见区域、预留区域及高度缓存；本实现采用公开的 TanStack Virtual，将同一思路接入现有会话组件。

- 根据可见区域挂载消息，额外预加载相邻一条；完整历史保持在数据层，滚动区域保留全历史高度。
- ResizeObserver 缓存实际行高；上方估计高度被校正时补偿滚动位置。已经访问的消息保留原有 DOM、Markdown 和组件状态；离屏时通过 content-visibility 暂停布局与绘制。仅在切换会话后释放已加载内容和高度缓存，新会话重建列表并校正至最新消息；宽度改变后重新测量换行高度。
- 滚动更新由 React 批处理，不强制同步提交；仅位置与高度变化时直接更新列表容器，避免仅位置变化时重新提交卡片。
- 正文复用 MemoizedMarkdown，无批注时不生成新的空状态；历史正文跳过逐段动画扫描，目录标题与预览只在数据改变时解析。
- 搜索保留完整历史的计数和全局索引，仅补载命中位置附近，已加载内容继续保留；目录和批注跳转走相同虚拟索引。旧授权及重新生成仍按完整历史中的最后用户消息判断。
- 上滚暂停跟随，回到真正的底部后恢复；下方流式增长不能移动正在阅读的内容。

## 实际验证

脚本：scripts/qa-long-conversation.js。240 条消息首屏的可见与预加载区域为 2 条，初始高度校正期间共缓存 7 条；24 次连续原生滚轮操作期间可见与预加载区域为 2–5 条。上方已测量行增高 80px，阅读锚点偏移 0px。目录跳转、唯一早期命中、多处命中导航的可见区域各为附近 3 条；完整历史仍统计 120 处重复命中。追加后为 242 条，流式增长保持底部；暂停后继续增长，阅读锚点偏移 0px。返回已加载内容时，回复容器和 Markdown DOM 是同一对象；切到子会话后原缓存 DOM 全部断开连接。再次返回会话新建缓存，保留 5 条已访问消息、可见区域为最新 2 条，底部距离 0px。

浏览器结果与截图：/tmp/selection-virtual-chat-qa/result.json、latest-page.png。单元测试覆盖完整滚动范围、上方高度补偿、下方增长不移动阅读位置和离屏高度缓存；现有滚动、回答标识、目录及分支回归保持通过。

这是渲染优化，未改变服务端历史加载协议或模型上下文。单条超长回复仍完整解析 Markdown，未实现段落级虚拟化；本验收不能代表所有真实会话与机器上的 FPS。
