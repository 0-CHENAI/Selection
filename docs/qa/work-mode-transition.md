# NORM / PRO 内容衔接

## 2026-10-12：缩短过渡并默认进入新建会话

基于 `ce81b77f5` 的本地试用改动。列表和当前聊天的原生快照改为 150 毫秒纯透明度交叠，使用 `cubic-bezier(0.22, 1, 0.36, 1)`。取消大区域的 0–2px 模糊，动画时长由 360 毫秒缩短至 150 毫秒。旧运行时降级路径采用相同的纯淡入；减少动态效果时同样没有模糊、位移或缩放。顶部选择底板、草稿、同步提交和快照边界沿用现有实现。

切换至另一种模式时，统一导航到该模式的新建会话界面，并禁止自动选中历史会话。移除记忆上次会话的导航状态，避免切换时恢复长对话。两种模式仍分别保留草稿和输入设置；此时只显示草稿输入界面，首次发送才创建实际会话。点击当前已选中的模式不改变当前会话。

本轮验证：

- 实际组件和固定传输数据的浏览器验收通过，四组原生快照动画均为 150ms，过滤器均为 `none`。60ms 采样时旧 / 新透明度为 `0.0828531` / `0.917147`，透明度之和保持 1。
- 双向独立草稿及原模型保留；只有一个输入框。快速点击取消、导航优先、375px 顶部导航、键盘 Space / Enter、减少动态效果及旧运行时降级均通过。完成后没有残留截图名称、过滤器或点击限制。
- 新建会话落点改动后，34 项模式导航、草稿、草稿转会话、导航协调及列表操作测试通过；Electron 类型检查和修改文件 ESLint 无错误（AppShell 保留原有 Hook 警告）。renderer 生产构建通过，保留既有资源块大小提示。
- 原生 Electron 使用实际历史 PRO 长对话复验：切至 NORM 后路由为 `allSessions`，显示 NORM 新建会话；切回 PRO 后仍为新建会话，不恢复历史对话。未发送消息或创建实际会话。
- 截图位于 `/tmp/selection-mode-fade-qa/`。预览浏览器即使空闲也存在约 1 秒的帧回调节流，因此不据此报告原生桌面 FPS 或端到端加速倍数。本轮没有重新测量真实长对话的原生窗口性能。

## 历史记录：2026-10-05

2026-10-05，基于 `version-3.0` 的 `34f77e125`。

顶部模式选择的选中底板沿用现有 Motion 库做共享布局滑动。模式切换使用 Chromium 原生 View Transition 保留旧画面，在列表与当前聊天的内部内容之间做 360 毫秒柔焦交叠：旧内容从清晰淡至最多 2px 模糊，新内容从 2px 模糊逐渐清晰。两幅画面使用相同缓动 `cubic-bezier(0.4, 0, 0.2, 1)`，无中间空白；不移动或缩放内容，不做翻页。模糊只作用于短暂的截图层。原来 240 毫秒的快速缓动在前 60 毫秒已经完成约 83%，原生窗口有动画却看起来像硬切；调整后的前 60 毫秒只完成约 9%，让主页面的交叠更清晰可见。

聊天窗口的背景、圆角、边框及阴影留在原来的 `PanelSlot` 外层，只有内层进入截图动画；顶部与固定侧栏不进入截图。多个聊天面板中只处理当前面板。动画不额外挂载聊天组件或输入框，不改变会话、草稿和权限的状态管理。

系统开启减少动态效果时，取消模糊，内容只淡化 150 毫秒，顶部底板直接更新位置。缺少 View Transition API 时使用相同幅度的入场柔焦动画降级，并同样遵循减少动态效果设置。重复点击及其他导航会取消尚未提交的模式更新，工作区切换与卸载会清理动画。

设计参考 [Beautiful UI Chat 的固定内容区域](https://www.beautifului.dev/#chat-composer) 与 [beUI Morphing Modal 的内容柔焦交叠和缓动](https://beui.dev/components/motion/morphing-modal)。只借鉴内容衔接，未采用示例中的高度变化、位移或缩放。实现使用原生 API 与项目已有动画库，无新增依赖。
