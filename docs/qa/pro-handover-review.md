# PRO 交接修复后的代码与业务逻辑复审

日期：2026-10-05。基线：`fcffa40b5`，本地 `version-3.0`。

本轮审查覆盖工具执行前拒绝、SDK 原始执行记录、交接快照与文件来源、未知操作复核、完成操作防重放，以及根会话和 worker 的权限约束。继续沿用现有交接协议，没有新增依赖或更改界面。

## 已确认并修复的缺陷

| 级别 | 触发与影响 | 修复与验证 |
| --- | --- | --- |
| P1 | SDK 复用调用 ID 时，旧完成结果被后一次覆盖；没有 UI 工具消息的 SDK 操作不进入快照。目标可能丢失已完成操作的防重放依据。 | 按 SDK 调用发生次数保留独立身份、原始参数、状态与证据；UI 仅补充没有 SDK 身份的旧记录。宿主测试确认旧 Write 和隐藏发布仍禁止重放，执行前被拒绝的新 Write 可执行。 |
| P1 | SDK 参数验证、工具查找和 before-tool 拦截发生在执行包装器之前，未执行的调用仍变成未知结果并阻塞 PRO。 | 通过实际 SDK 执行后 hook 与结果内容引用区分执行和准备拒绝，不猜测错误文本。真实 SDK loop 测试覆盖无效参数、缺失工具、前置拦截、执行异常、后置 hook 异常及并发复用 ID。执行后失败保持未知。 |
| P2 | WebFetch 复用调用 ID 时，最新 URL 参数可能与第一次响应内容配对，冻结来源错误。 | 来源捕获复用同一 SDK 调用发生记录，逐条配对 URL 和原响应；没有 UI 消息的成功请求也保留。缺少原始调用参数的旧回执使用可用 UI 参数补齐，仍以 SDK 结果作为内容。测试核对三个来源的 URL 和冻结字节，不重新访问网络。 |
| P2 | `operations.json` 即使缩进，单个长 evidence 字符串仍可能超过原生 Read 的 50KB 单行限制，导致复核无法开展。 | 衍生索引把证据分为每块最多 4096 个 Unicode 码点的 `evidenceChunks`，无分隔拼接恢复原文；不截断证据。实际 Read 验证长中文、emoji 和转义文本可读；每行低于限制。旧索引先验证再原子升级，损坏索引拒绝，冻结记录不变。 |
| P2 | 用户已保存复核后，宿主放行，但模型背景仍显示旧 `unknown`，模型会继续要求用户复核或自行拒绝执行。 | 模型背景展示生效的复核状态和剩余未知数量，保留冻结原始证据。回归测试确认复核后未知为零，后续 PRO→NORM 交接也保留结果；已完成操作在目标和 worker 中仍禁止重放。 |

同一个 SDK 批次存在重复 ID 时，回执不能确定属于哪次调用：本轮保留两次请求及未归属的原始结果，保持未知，不将一份成功回执错误分配给多个操作。旧回执缺少 SDK 参数时，保留现有 UI 请求身份用于防重放。

## 代码质量与兼容性

执行状态与网页来源共用调用记录解析，避免两条路径采用不同的结果匹配规则。使用 Set/Map 替代重复 UI 扫描，快照和索引内容读取后只计算一次实际内容 hash。执行判定使用 WeakSet 保存内容引用，不依赖可复用调用 ID，也不会长期保留已释放的结果。

不可变交接快照、来源文件 hash、普通目标权限和源工作流所有权约束继续生效。未确认的脚本或外部操作没有被自动放行；单纯聊天确认仍不能替代保存复核。派生索引升级只接受从已验证冻结快照得到的旧格式内容。
