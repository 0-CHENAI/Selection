## F1–F6 实际入口与验证

- F1：`PiEventAdapter` 使用最新快照，临时缓存最多 64 Ki 字符；明确空的最终结果也不能被旧输出覆盖；结束后的更新被忽略。
- F2：`wrapSingleTool → compactToolResult → PiEventAdapter → SessionManager → tool_progress → TurnCard`，包含 Office 子会话的原工作行。大结果默认最多约 4,000 估算 token 后进入原文落盘与约 2,000 字符首尾预览。原文写入失败时保留原结果；OfficeCLI 原始指南及显式历史读取合同不被削弱。
- F3：真实 `toolcall_delta` 产生限频活动；不传未完成代码。`context-budget-stream` 在成功、失败、取消、预检拒绝时记录元数据。每个 SDK 会话 `diagnostics/model-requests.jsonl` 最多 1 MiB，加一份轮转备份；单条最多 4 KiB。只保存用量、时间、数量和 SHA-256 指纹，不保存提示、工具参数、凭据或错误正文。首字节/事件/输出是最后一次 HTTP 尝试的时间，整轮耗时含重试和排队；不可直接叫作上游计算耗时。
- F4：`waitForBridgeReply` 在发送前注册请求，信号取消与关闭清理等待；普通执行回包以 10 分钟兜底；`spawn_session(mode=wait)` 加上既有子任务等待预算，权限审批、用户澄清、协调者求助和 `run_task(waitForCompletion=true)` 由原业务等待及取消机制管理。超时原因贯通主进程，停止本轮、回收旧运行时并明确结果未知。原有 Bash 退出/关闭探针和显式 timeout 继续使用，不按无输出判死。`settleCheckpointTool` 不会把 unknown 从待确认操作中移除。
- F5：随包入口 `"$CRAFT_BUN" "<ppt-design>/engine/inspect-deck.mjs" "<deck.json>" 1 6`，每次最多 12 页，返回原文路径、页索引、结构数量和截断说明。样本测试用 100 页 × 200 个文字元素验证输出有界、原文不变及 CLI 可执行。选页摘要不替代事实/来源核验或质量检查。
- F6：`LatestTaskQueue` 合并同一会话的连续更新；原 `deck watcher / exportIncrementalPptx / Office preview` 合同继续使用。测试覆盖同路径页数增长、坏输入保留旧文件、锁定目标失败后原文件不丢、最新停止状态、多会话隔离和失败后继续。

## 保留的边界与后续验收

1. 现场缓存命中下降的原因仍未证实。已补稳定系统/工具指纹和 cacheRead 等用量，不引入重复缓存层，不承诺固定速度提升比例。需要下一次真实慢任务的数据才能继续归因。
2. 未使用真实用户材料或付费模型重跑那次约 270 秒的生成；上游模型实际生成时间不会因新增状态而消失。
3. 本轮有自动化预览状态与页锚点回归，未把桌面真实视觉验收、Windows 锁文件实测或发布后体验宣称为完成。锁文件使用可控 EBUSY 故障注入。
4. 取消代理等待不代表远端副作用一定被撤销。超时/取消后的未知操作必须核对实际结果；不会自动重放。
5. 尚未合入部署。当前正在运行的已安装应用不会自动采用工作树源代码修改。
