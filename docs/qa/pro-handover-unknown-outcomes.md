## 修复行为

- 工具包装器保存运行时执行结果。执行前被拒绝的调用，以及仅完成数据源指南准备、尚未调用业务工具的请求，记录为 `not-performed`；外部工具不能用自己的返回元数据声明免检。已开始执行的通用失败仍为 `unknown`。
- 原生文件操作跟踪写入/目录创建是否开始。文本匹配失败等写入前失败可以确定未执行；开始修改后报错，或已有该调用的文件回执时，继续保留不确定性。
- 新快照使用 SDK 原始结果确定状态。旧版原生 Edit 的两类精确匹配错误也能识别为未执行，但不信任 UI 展示字符串或外部同名报错。SDK 已有参数时，不再因 UI 缺少 `toolInput` 误判；成功输出中提到“未知”也不会单凭词语触发阻塞。
- 重用调用 ID 时清除上一调用的结果；未完成的执行检查点不能被旧 UI 完成状态覆盖。缺失请求身份的已完成操作仍禁止重放对应工具。
- 提供单独的 `operations.json`，由冻结快照生成、按完整性校验读取。旧目标在下一回合补齐索引；新目标的 `snapshot.json` 使用缩进格式。背景和拦截结果明确指向原生 Read 及会话标题菜单的“查看交接”，说明需要保存复核依据，避免继续尝试同样会被拒绝的脚本或委派。

未知外部操作、部分写入、损坏的检查点仍要求复核；完成操作不能重复执行；正常权限校验和源工作流所有权限制仍然生效。
