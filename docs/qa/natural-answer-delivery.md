# natural-v1 答案交付（取代 submit_answer）

日期：2026-10-13。

## 协议

- 普通会话不再注册 `submit_answer`。本回合最后一条**不带工具调用**的 assistant 消息就是答案；运行结束后，主进程直接把这条草稿原地提交为答案：校验、持久化，回读确认后再发布。消息 id、SDK 锚点和渲染节点都保持不变。
- 最终答案不要求标记。Pi 适配器的 `AnswerBoundary` 仅兼容历史或误写的 `<<<FINAL_ANSWER>>>`，在标记处切分：
  - 标记之前：`phase: intermediate`；
  - 标记之后：`phase: final`，直接流进答案卡片。
  - 标记和答案写在同一行也能识别，标记不会泄漏到正文。
- 没有标记时，整条消息也实时显示；运行结束后以原消息身份提交。Codex 自带的 `commentary` / `final_answer` 阶段保持原有分离，不把过程说明并入答案。
- 只有运行结束时没有最终正文，才发起一次纯文本收口；收口步骤不开放任何工具。收口仍无正文时，回退到最新草稿（salvage）；仍失败则报告 `answer_delivery_missing`。
- 内部协调检查点保持原行为：正文私有，不提交答案。

## 展示（2026-10-13 修订：无框回复）

- 流式期间无法可靠判断一段正文是不是最终答案，所以不再判断：回复整体去掉卡片外框（背景、描边），过程正文和答案用同一种样式实时显示。计划卡片保留原有框。
- 每段文本按文本流 id（一次运行内唯一的子回合 id）作为块的 key。
  - 消息以工具调用结束：这一块执行"并入思维链"退场：上移 10px、缩放 0.985、模糊 2px、淡出，同时高度收起。这段文字同时进入工作链，工作链标题的预览和步骤数同步更新。
  - 高度收起与工作链标题出现使用同一 280ms 缓动，所以首次出现标题时，整轮总高度也只减不增。实测 MO 回放：81→58→43→36→32→30px，没有回升。
  - 消息以 stop 结束：服务端原地提交，块和 Markdown 不重新挂载，揭示动画不重播；底栏操作按钮在预留的 40px 行内淡入。
- 不再依赖 `<<<FINAL_ANSWER>>>` 标记，提示词和逐轮提醒都已移除；解析器仍会剥掉历史或误写的标记。
- 流式输出中尚未闭合的 `datatable`、`mermaid`、`json` 等富块先显示 48px 占位，闭合后再渲染。

## 验证

- 自动化：answer-delivery（服务端）、跨层 pipeline（服务端 → renderer → 落盘重载 → 分组）、AnswerBoundary、streaming-rich-fence、guard/bridge、UI 源码断言；`typecheck:all` 通过。全仓库测试使用既有逐文件隔离入口，避免全局 mock 与配置导入的相互污染。
- 先前真实模型验证（连接 `pi-api-key-2`）：`QA_MODELS=MO,Laufry bun run scripts/qa-natural-answer.ts`。
  - MO / Laufry 共 12 个回合（含工具与无工具）：0 次收口，提交在最后一个增量后 3–14ms 完成，流式正文与提交正文一致，标记 0 泄漏，0 个 `answer_preview`。
  - 当时包含标记提醒；当前已移除提醒，并允许无标记答案。这些历史结果不能替代移除提醒后的真实模型验证。
- 浏览器回放：`ego-browser nodejs < scripts/qa-natural-answer-ui.js`，用生产 processor、分组和 TurnCard 回放上述真实事件。
  - 4 个回合中，高度回落只发生在气泡退出时，每帧最大回落 ≤ 32px，为连续动画；没有其他回落。
  - 答案卡片出现后从未消失；气泡最大高度 99.5px。
  - 修复富块占位之前，Laufry 的 datatable 回合有一次 166px 的单帧回落。

## 2026-10-14 质量与业务逻辑审查

- 原生 `commentary` / `final_answer` 优先于可选标记解析，防止过程文字与答案被拼成一条。转发事件即使省略 `api` / `provider`，仍按文本签名中的阶段分类，并保留最终正文原有的流身份；新增适配器混合阶段及缺少提供商字段的回归。
- 认证、来源和进度续跑只由当前执行产生的错误阻断答案提交，保留历史错误记录；当前执行遇到错误仍不自动收口或提交。
- `Answer delivered.` 等旧成功回执不作为自然答案或 salvage 候选。服务端与前端统一过滤，回执后最多进行一次正文收口，验证发布和落盘均为正文。
- 下层 SDK 执行守卫拒绝所有旧 `submit_answer` 别名，即使工具单独调用或同批其它工具已完成；业务工具和协调决定保持原有边界。
