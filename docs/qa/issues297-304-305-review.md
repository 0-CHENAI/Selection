# #297 / #304 / #305：恢复与运行历史审查

## 问题、原因与修改

- #304：定义节点只保留一个 sessionId，导致并行实例互相遮蔽。现在保留阶段汇总及全部实例行，每个实例独立关联当前会话与历史尝试；子会话创建完成立即广播入口，无需等节点完成。
- #305：终态被隐藏，且初始化只读取整个任务的最新 run。现在按父会话读取全部运行记录，允许选择历史 run；使用运行冻结定义中的标题，任务后来编辑或删除不会替换旧图。选择历史时，新 run 的事件不会抢走当前选择。
- #297：已有请求诊断、有限退避与复杂 DAG 恢复保留；主会话现在可检查失败尝试并显式重试最近一次失败运行，提示工具操作可能再次执行。使用 continue 恢复合同，不将 paused 的 resume 接口用于失败运行。停止/完成历史不提供重试按钮，其他活动 run 存在时不显示该入口。

## 代码质量与业务审查修复

- 历史重放新增 view 模式，不注册完成监听、不启动审批/协调器计时器、不调度、不改写日志；终态最新运行读取也使用此路径。
- 运行筛选严格绑定 workspace、task slug 和父会话；不将缺失父会话归属的旧日志猜成当前会话。
- 先订阅事件，再加载历史；请求期间收到的新状态覆盖初始快照。组件按 workspace/task/session 隔离，避免切换父会话时残留旧入口。
- 保留每次尝试的 sessionId、编号和终态；历史读取与实时更新使用同一尝试归并逻辑。
- 修复 Stop 与异步子会话创建之间的竞态：迟到创建保留可审计记录但不发送提示词；停止后的派发错误不把 stopped 改回 failed。finally 清理保留原合同。
- 历史耗时采用持久化指标，旧记录回退为日志时间差，不随读取对象创建时刻变化。
- 重试增加同步防重入门禁；失败冲突反馈可见，不自动循环重试。
- 新增 Windows/Linux 专项工作流，覆盖 TaskRunner 恢复、进度面板及真实 Pi SDK + 本地 HTTP 故障服务。修正 SDK 测试的 Windows 动态导入路径为 file URL。

- 进度面板渲染覆盖：三实例、旧尝试、冻结标题、已停止状态不被 runningHint 覆盖、历史 run 选择。
