# #456 多前提研究、共享问题与条件式交付验收

沿用 #455 的研究记录及 #454 的执行日志、规范节点和原子 revision。研究线、共享问题与语义关系是同一运行的业务背景；调度仍由已有执行 DAG 决定。

## 公共约定

| 能力 | 实际入口与边界 |
| --- | --- |
| 多研究线 | `research.ts` 的 primary `line` 与追加 `lines`；稳定 id、问题、前提、父线和来源引用。多线 claim 必须声明 lineIds，专用节点可绑定 researchLineIds；修订不得改变原 claim 的前提归属 |
| 共享后续问题 | `research-expansion.ts` 的 expandResearch；既有 patch 同时追加问题与 canonical researcher 节点。问题保存地区、年份、币种、税、计算口径、输入要求及明确兼容原因；每个父输入保留 premises、claim/version、证据、异议和实际执行路径 |
| 登记与竞争 | question id → sharedTaskRef 由同一 revision/log/checkpoint 持久化。相同问题重读并复用已登记任务；过期 revision 整体拒绝，不另开执行。已有父上下文不可丢弃，不能以标题相似或推荐相同推定兼容 |
| 精确推理输入 | inputClaimRefs 关联具体事实版本；输入变化使受影响的推断审查失效。固定原文的定位与逐字摘录在宿主校验，字面量反斜杠 n 不能冒充原文换行 |
| 语义关系 | supports/refutes/converges 引用精确 claim 版本，有产出者与当前/历史标识；不变为执行依赖，不合并双方原有历史 |
| 后继与复用 | 同执行根的已停止/完成前驱经既有安全点检查后可创建规范后继；兼容研究标准、旧执行凭证和 records hash 验证通过才继承。已完成共享问题仍引用原生产节点，即使后继只调度受影响部分；当前来源变化及精确输入变化使相关审查失效 |
| 异议 | 仅明确的 correct + revisedClaimRef、且新版本独立支持，才能将该异议派生为 resolved。数字或口径修订不能自动关闭同一旧 claim 上暂存的市场异议；回应、限定及暂存仍披露 |
| 报告与交接 | 条件式报告分别写前提、依据、当前审查与限制，并要求 alternatives/changeEvidence。总覆盖按每条线×必答维度计算。Handover 复制同一当前版本、双方父输入和各线未覆盖问题到新 NORM |

根/worker 提示只投影相关当前业务背景与来源版本/快照路径，不反复拼接整个业务历史或来源全文。历史父 claim 可通过原生产 run/node/receipt 回查；结果查询与界面保留完整凭证。

## 确定性恢复与边界

F6-c 验证同名但不同年份或税口径拒绝共享；推荐趋同仍保留双方研究线、审查及异议。F6-b 验证同 revision 两请求只登记一次，落盘失败整体回滚，重建仍只有原 question/task 身份。F6-d 验证更换成本来源后，只重新核验受影响成本；未变风险来源的独立审查和原生产 run 保留，旧报告未改写，新报告引用新成本与旧风险的有效版本。后继保留已完成共享问题，无需重复安排原共享任务。

真实运行发现并修复了四项宿主边界：并发结果导致 checkpoint 更换时，结果与拒绝回执返回当前 checkpoint，过期竞争不计为结构错误；接受决定后明确让模型结束本回合，下一 checkpoint 由宿主发起；verdict 修订的 node-retry 在结果读取和执行恢复中使旧节点回到待执行，新的执行完成前不会显示旧成果为当前完成或直接进入验证；Handover 保存前后继关系，将旧成果标为 task-history，只从当前后继派生执行待办、研究缺口和计划目标。旧报告与来源仍完整保留。回归包含刷新后必须真正执行修订，以及原 repair 计数仍保留。

驱动 `bun scripts/selection-3.0-f6.ts` 使用实际 SessionManager/TaskRunner、gpt-6-luna、low、safe，以及冻结 utilization.txt/price.txt。模型实际读取原文、原生 deep-research Skill，通过既有工具追加 canonical Q-price 与独立 reviewer，不以伪造输出替代模型审查。[结构化记录](selection-3.0-research-lines.json) 保留精确生产与审查凭证、所有尝试和实际工具调用。

| 尝试 | 实际结果与处理 |
| --- | --- |
| 初次与第二次 | 过期 checkpoint 竞争先触发结构错误暂停、后进入无效轮询。停止后修正当前 checkpoint 回执与回合结束指令，两次失败及调用保留 |
| 主流程 run-1791084065730 | 原子追加一个共享电价任务；电价独立审查后暂停、落盘、清理并重建实例，恢复仍是原 task/run/question。价格未重跑。高利用率推荐经实际 FAIL 和修订为 v2，低利用率 v1 保留；最终成本一条 covered、一条 limited，风险两条 uncovered。宿主允许明确限定交付，但此结果尚未满足本案例的两条成本覆盖验收 |
| 后继 run-1791085831139 | 明确创建仅含高利用率原事实修正、独立复核、当前报告三个节点的规范后继。fixed-high@2 被实际 reviewer 支持；共享电价与低线生产/审查凭证未改、未重跑。两条成本 covered、两条风险 uncovered，blockers=[]，实际根提交 PASS。市场异议仍 limited，原审计异议通过明确 correct/revisedClaimRef 解决 |
| 完成后核验 | 首次脚本选中历史报告、另有数字千位分隔断言问题，均作为驱动失败保留；修正后只重新读取已完成实际运行并创建新的不可变交接，不调用模型。新 NORM 261004-polished-coast 的当前报告精确版本与后继一致，旧报告单独保留为历史 |

最终高利用率 9000 小时选择 A（99000 对 180000），低利用率 1000 小时选择 B（91000 对 20000），各自前提、独立依据和地区/年/税限制保留。共享问题保存双方精确 claim/evidence/issue/path 和六项范围；原价格节点在整个前后继日志中仅启动一次。两个风险维度未覆盖，市场异议及需新增需求/可靠性证据的条件仍写入报告，不记为无条件整体推荐。

资源记录按 sessionId+startedAt 去重累积 currentTurn/lastTurn，取最大值，包含根规划、审查、失败调用与重试。主流程及后继共 201 模型调用、5816447 未缓存输入 token、7529472 缓存读取 token、85524 输出 token；前两次独立失败另计 69 调用、987968 未缓存输入、1371136 缓存读取、15377 输出。失败记录中主流程/后继的账本与成功谱系重叠，不能重复相加。一次无提供商用量的尝试标记未知；costUsd=0 未报告价格，不能解释为免费。并行回合耗时不相加为任务耗时。

本例发生较多根会话历史查询、检查点竞争和上下文压缩，实际开销很高；记录用于暴露限制，不据此声称效率提升或普遍模型质量优势。reporter 曾尝试 Bash true，被只读工具边界拒绝，未产生文件或外部效果，失败调用仍计入开销。
