# v2.1.0 — Selection

## Improvements

- **最终正文按语义块渐显**：保留完整 Markdown 文档，以短促的段落渐显和长块按行呈现替代字符裁切；历史内容不重播，选择文本、手动滚动和减少动态效果设置会停止动画。复制与完成状态不再等待视觉播放，修复流式布局等待期间用户离开底部仍被拉回的问题。([#279](https://github.com/0-CHENAI/Selection/issues/279))

- **流式正文持续渐显** — 活动段落和代码块只对新增行进行短过渡，旧内容不重复淡入；修复普通输入关闭动画、视口外段落丢失渐显和持续输出时滚动跟随滞后的问题。选择正文立即显示完整内容，历史消息不重播，完成后快速收口。([#328](https://github.com/0-CHENAI/Selection/issues/328))

- **编排编辑入口说明更明确**：使用节点连线图标及“编辑任务编排”名称，说明修改任务定义而非会话内容或运行历史。键盘可发现用途说明，触屏和紧凑布局先说明、再明确进入编辑器，保持原定义预填与导航行为。([#282](https://github.com/0-CHENAI/Selection/issues/282))

- **HTML 全屏预览支持统一缩放与平移** — HTML 全屏此前固定为 1:1，iframe 内手势也不会到达父页面。现在复用富块缩放工具条与手势，桥接沙箱文档内的滚轮、捏合、键盘和拖动，同时保留链接与禁止脚本的沙箱合同。切页和重开复位到 100%，适应视口计算包含内容边距，缩放不加入动画。([#327](https://github.com/0-CHENAI/Selection/issues/327))

- **会话内 Mermaid 图支持缩放与拖动平移** — 会话内 Mermaid 过去只能横向滚动或点进全屏，现在复用统一缩放逻辑：图内滚轮以指针为中心缩放、左键拖动平移，短点打开全屏而拖动不会误开，并提供复位入口。同时修复全屏 Portal 延迟挂载导致滚轮监听缺失的问题，图片预览改用同一容器挂载方式。([#334](https://github.com/0-CHENAI/Selection/issues/334))

## Bug Fixes

- **显式交付完整正文，防止主要答案折叠与覆盖** — 模型先讲解、调用工具验证、再输出短补充时，原有分类会把主要答案折叠进工作链。现在普通用户回合启用 `submit_answer({ markdown })`：模型提交完整正文，服务端验证并持久化后发布唯一正式答案，后续短句或工具回执不能覆盖它。交付入口统一校验回合身份、前台工具与 Swarm 聚合条件，防止重复／并行交付，同批含业务工具时拒绝提交；漏交付时最多增加一次同模型、同上下文的隐藏收口且仅允许答案工具，失败则保留过程并报告未完成交付。([#330](https://github.com/0-CHENAI/Selection/issues/330))

- **模型选择器的「模型」提示不再滞留在按钮上方**：桌面输入栏关闭模型下拉框时（点击别处、选中模型、按 Esc、或关闭思考等级子菜单后关闭）不再把焦点交还给触发器，因此提示不会残留、输入框保持可输入，悬停与键盘聚焦时的提示行为不变。([#332](https://github.com/0-CHENAI/Selection/issues/332))

- **Windows 窗口按钮融合与关闭会话提示遮挡** — Windows 原生窗口按钮改为透明背景，不再与应用主题之间形成突兀色块，同时保留 48px 高度、主题图标颜色与按钮避让间距；面板标题按钮（含关闭会话）的悬停提示默认向下显示，不再被原生窗口按钮区域遮挡。([#319](https://github.com/0-CHENAI/Selection/issues/319))

- **分支会话独立持久化，删除会话时可靠清理** — 分支会话过去虽复制了正文，却仍依赖源目录的 SDK 历史、也缺少实际附件文件。现在新分支拥有自己的附件、输出文件与 SDK fork 输入，重启后恢复分支已有的 SDK 会话，不再因重新从源历史 fork 而丢失续聊。删除前会迁移依赖源目录的旧普通分支并确认路径落盘，删除覆盖磁盘上的独有会话、等待运行时初始化与 SDK／MCP 关闭和持久化写入完成，阻止迟到事件重建目录，清理失败给出明确报错。([#325](https://github.com/0-CHENAI/Selection/issues/325)、[#322](https://github.com/0-CHENAI/Selection/issues/322))

- **统一应用内业务确认与取消行为** — 删除会话、退出登录及项目／工作区／编辑放弃等确认此前混用系统弹窗与 `window.confirm`，现在统一使用应用内 AlertDialog：文案跟随客户端语言，取消为默认焦点，危险操作使用 destructive 样式。本地与远程服务端请求由发起客户端显示并返回决定，WebUI 复用同一合同；无界面、卸载、异常及重复请求都不会批准操作。批量删除一次明确显示总数量，并修复取消删除也清空会话选中状态的问题，菜单确认关闭后恢复触发按钮焦点。([#278](https://github.com/0-CHENAI/Selection/issues/278))
