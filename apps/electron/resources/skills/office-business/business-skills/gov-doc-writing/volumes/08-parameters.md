# 六个参数

动笔前先把下面六项对齐。缺一项就问，不要用样例里的机关、文号或数据填上。

| 参数 | 要确认的内容 | 还没有时 |
| --- | --- | --- |
| 文种 | 对方读完要做什么：批准、知晓、执行、商洽或记录 | 按用途建议一个文种，等用户点头 |
| 发文机关 | 落款上的全称，不用简称冒充 | 待补充：发文机关 |
| 主送 | 收文机关。请示只能有一个主送 | 待补充：主送机关 |
| 单位性质 | 党委机关、政府及部门、事业单位、国有企业、基层组织，或其他 | 先问一句，不默认成政府 |
| 角色 | 谁在写：文秘代拟、署名人本人、基层办事人员 | 代拟时不要写成署名人的私人承诺 |
| 场合与方向 | 上行、下行、平行，或面向社会公开；会议、汇报、部署哪一种场合 | 结尾用语先空着，不混用「请批示」和「请遵照执行」 |

## 单位性质怎么影响写法

只改语气和该问的事实，不改用户没给的政策口号。

- 党委机关：先写依据和程序，再写事项。没有会议或批复记录时，不写「经研究决定」。
- 政府及部门：事项、责任单位、完成时间要能核对。
- 事业单位：对主管机关用上行，对服务对象用周知，两套结尾不要焊在一篇里。
- 国有企业：经营数字只来自用户表格。没有董事会或党委会记录时，不写「已前置研究」。
- 基层组织：句子短，对象写具体到村或社区。不编发文字号。

## 角色

- 代拟：稿末用「供修改」，不替领导签字，不写「我代表班子保证」。
- 本人：第一人称只出现在用户要求用本人名义的述职、讲话里。
- 基层办事人员：不扩大职权。做不到的审批写成「请某机关办理」。

## 用户说「你看着写」

「你看着写」「你定」「随便写」只表示用户暂时不改提纲，不表示可以编事实。

1. 先用一句话复述你准备用的文种和方向。
2. 只追问这一文种事实清单里还空着的项，一次问完，不超过八个问句。能用会话里的 `clarify` 时用它，否则写在同一条回复里。
3. 用户仍不补：交提纲，并把空项标成「待补充」。不交一份看起来已经填完的稿。
4. 不要为了填满篇幅去引用没给过的文件、数据或领导讲话。
