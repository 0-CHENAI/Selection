# 动笔前

每次起草先读 [08-parameters.md](08-parameters.md)，把六个参数对齐，再做下面的事。用户说「你看着写」时按那一册追问，不跳过。

## 1. 确认文种

向用户确认这件文要对方做什么：

| 目的 | 常用文种 |
| --- | --- |
| 发布应当遵守的事项 | 通知、通报、决定 |
| 请求批准或指示 | 请示 |
| 汇报情况、答复询问，不要求批复 | 报告 |
| 不相隶属机关商洽 | 函 |
| 记载会议议定事项 | 纪要 |

法规、规章和规范性文件的制定程序不在本技能里替代。用户只给了一堆材料、没有文种时，按上表提出一个文种并说明理由，等用户确认后再写标题。

## 2. 列出已有事实

从材料里摘出发文机关、主送机关、事由、时间、依据文件、联系人。每一项记下它出现在哪一份材料。摘不到的项目进入待补充清单，不写进正文当事实。

## 3. 问清缺口

至少问清：谁发、发给谁、要对方做什么、到什么时候、依据是哪一份文件。用户暂时答不出的，稿中保留「待补充」，并在文末用一句话列出还缺什么。

## 4. 选定结构册的一节

只读 [03-structures.md](03-structures.md) 里对应文种的那一节。通知不要套请示的结尾，纪要不要再写「妥否，请批示」。

公开属性、印发范围、是否需要版头版记，在动笔前一并确认。用户没说公开范围时，版记里写「待补充：公开属性」，不默认写成公开发布。

## 5. 按文种核对事实

选定文种后，只核对这一张表里的行。打勾的项在材料里找不到，就列入待补充，不写进正文当事实。

| 文种 | 必须能指出来源的项 |
| --- | --- |
| 决议 | 会议名称、时间、表决结果、事项、生效日期 |
| 决定 | 事项、依据、执行主体、生效日期 |
| 命令 | 职权依据、令号、施行日期；任免还要姓名和职务 |
| 公报、公告 | 发布机关、公开事项、日期；不写内部主送 |
| 通告 | 范围、依据、事项、生效时间 |
| 意见 | 问题、原则、分工、方向（上行、下行或平行） |
| 通知 | 主送、事项、责任主体、完成时间 |
| 通报 | 事实、处理或情况、知晓范围 |
| 报告 | 主送、已发生的事实和数据；不要批准事项 |
| 请示 | 一个主送、一件事、请求批准的具体内容 |
| 批复 | 来文标题、是否同意、要求 |
| 议案 | 提请对象、审议事项 |
| 函 | 商洽对象、事项、是否为复函 |
| 纪要 | 会议名称、时间、已经议定的事项 |

讲话稿、方案、总结不进入这张表。它们不编发文字号。
