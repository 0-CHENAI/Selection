# 公文写作

能力参照 dsh-desktop gov-doc-writing，未复用其内容。

本技能由 Selection 自写。它覆盖 15 个法定文种的识别和骨架、GB/T 9704-2012 的版头、发文字号、标题、主送、正文层次、落款和版记，以及字体字号、行文关系和交付前自检。正文、分册和数字按公开的公文处理规则重新整理，不搬入无许可证的技能原文、模板或范文。

法定文种以党政机关公文处理工作条例中的名称为准：决议、决定、命令（令）、公报、公告、通告、意见、通知、通报、报告、请示、批复、议案、函、纪要。事务材料（方案、讲话稿、总结、汇报）可以协助整理，但不编发文字号，也不排成红色版头，除非用户明确要求按某一法定文种发出。

## 先遵守的边界

- 事实只来自用户材料和用户点名的附件。文号、主送、成文日期、签发人、印章、电话、数据没有出处时，写成「待补充：需要的内容」，不补造。
- 规范提法、机构全称、领导人职务和排序只照录用户给出的文字，不改字、不缩写、不凭记忆补写。没有把握就标待补充。
- 一次主送事项只办一件事。请示不夹报告，报告不夹请示。
- 文种由行文目的决定，不靠标题里的习惯叫法。路由若已标出文种，先按该文种起草，发现材料对不上时说明理由再改。
- 涉密材料和不必要的证件号、手机号、家庭住址不写入可外发的稿。
- 本技能是通用写法，不为单个行业预置政策口径。

## 十五个文种怎么选

| 文种 | 用来做 | 不要用来做 |
| --- | --- | --- |
| 决议 | 会议按权限表决后的事项 | 还没表决的设想 |
| 决定 | 对重要事项做出安排或奖惩 | 日常事务性布置（用通知） |
| 命令（令） | 公布法规、任免、嘉奖等，且用户确认有职权 | 没有职权说明的事项 |
| 公报 | 公开公布重要决定或会议结果 | 内部通报 |
| 公告 | 向国内外宣布重要事项 | 对某一系统内部布置工作 |
| 通告 | 在一定范围公布应当遵守或周知的事项 | 对上行文请示 |
| 意见 | 对重要问题提出见解和处理办法 | 代替请示去要批准 |
| 通知 | 传达要求、转发、任免或周知 | 批评和表彰（用通报或决定） |
| 通报 | 表彰、批评、传达重要情况 | 夹带请示 |
| 报告 | 向上汇报，不要求批复 | 在文中写「请批准」 |
| 请示 | 向上请求指示或批准，一文一事 | 多头主送、抄送下级 |
| 批复 | 答复请示 | 另加新的请示 |
| 议案 | 按法定程序向权力机关提请审议 | 没有提请对象时硬写 |
| 函 | 不相隶属机关商洽、询问、答复 | 对下级下命令 |
| 纪要 | 记载会议议定事项 | 把未定事项写成决定 |

每种的标题、主送、层次、结尾和易错点在 [03-structures.md](volumes/03-structures.md)。只读对应的一节。

## 文种速判

先看目的，再对文种。拿不准时停在这一张表，不要同时写成两种。

| 用户要的结果 | 用 | 快捷入口 |
| --- | --- | --- |
| 请上级批准一件事 | 请示 | 结构册「请示」，六个参数问主送 |
| 只汇报、不要批复 | 报告 | 结构册「报告」 |
| 布置或转发 | 通知 | 结构册「通知」 |
| 表彰、批评或传情况 | 通报 | 结构册「通报」；不发文时用事务册 |
| 不相隶属机关商洽 | 函 | 结构册「函」 |
| 记下已经议定的事 | 纪要 | 结构册「纪要」 |
| 会上讲、不发文 | 讲话稿 | 事务册「讲话稿」 |
| 个人向考核人说明履职 | 述职 | 事务册「述职」 |
| 安排工作和责任时间 | 方案 | 事务册「方案」 |
| 短篇幅报告一件已发生的事 | 简报 | 事务册「简报」 |
| 对着某份文件找差距 | 对照检查 | 事务册「对照检查」 |

用户说「你看着写」时，先读参数册的追问，不直接成稿。

## 版式要点

细目、字号和特定格式在 [05-layout.md](volumes/05-layout.md)。起草时先守住这些：

- A4。页边距上 37 毫米、下 35 毫米、左 28 毫米、右 26 毫米。
- 发文机关标志用小标宋、红色、居中。没有机关全称就标待补充，不用样例机关。
- 发文字号：机关代字 + 六角括号年份 + 序号 + 「号」。没有代字或序号就整行「待补充：发文字号」，不编一个像真的号。
- 标题 2 号小标宋，由机关、事由、文种组成，居中。
- 主送顶格，3 号仿宋，后加全角冒号。
- 正文 3 号仿宋。层次序数「一、」「（一）」「1.」「（1）」依次用黑体、楷体、仿宋、仿宋。
- 成文日期用阿拉伯数字，右空四字；没有日期就「待补充：成文日期」。不画印章。
- 版记在末页：抄送、印发机关和印发日期。未知就标待补充，不把成文日期自动当成印发日期。
- 落款不得单独成页：末段正文和署名设与下段同页、段中不分页。版记定位在末页版心底部。

## 交付前短清单

交稿前用第 7 册勾完。任何一项失败都先改稿。

1. 文种、标题、结尾用语一致。
2. 请示只有一个主送，报告没有「请批示」。
3. 机关、日期、数字、文号都能在材料里找到，否则是待补充。
4. 版头不是示例案例的机关名。
5. 字体字号和页边距符合第 5 册，或已写明偏差。
6. 没有伪造的签发人和印章。
7. OfficeCLI `validate` 已运行。页图用 `office_render` 原生读取，不用 OCR。

## 文件交付

用 OfficeCLI 写 DOCX。先 `officecli load_skill word`，步骤见第 6 册。不使用 python-docx，不调用 Python，不调用 LibreOffice。案例原件只读。套用案例时先 `office_template` 再 `office_template_write`；版头发文机关必须替换。宿主在写出和交付前跑版式守卫。需要看页面时调用 `office_render`，最多看三轮，禁止 OCR。
