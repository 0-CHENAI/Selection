# 议程与邀请函

用户要邀请函、请柬或会议议程时用本技能。成品是 Word。邀请函告诉对方来不来、何时何地；议程告诉到场后先做什么。两者可以在同一份文档里，议程用表格，不把议程写成会议纪要。纪要是会后的决定，本技能不写「会议决定」。

## 邀请函要写清

1. 称呼。不知道对方姓名就写职务或「尊敬的来宾」，不编人名。
2. 谁邀请、邀请参加什么。
3. 时间：日期和起止钟点。只有日期没有钟点时标「待补充：开始时间」。
4. 地点：能找到的地址或会议号。线上会议没给链接就标待补充，不要编一个会议号。
5. 需要对方准备的材料、着装或是否携伴。用户没提就不写「请着正装」。
6. 回复方式和截止日期。没给就标待补充。
7. 落款和发信日期。

语气按用户要求。年会、发布会对外用完整句、用「敬请」。内部周会用短句，不套「兹定于」。用户没说正式程度时，对外默认正式，对内默认简明，并在开头按这个选择，不两套语气混写。

## 议程表

列：时间、事项、负责人或主讲。时间段连续，中间空档写明是茶歇还是未安排。没有负责人就标待补充。不写讨论结论。

议程超过一页时，第一页仍能看到时间、地点和第一项。不要只在页眉放一个会标、正文却没有时间。

## 版式

- A4。标题居中，大于正文。正文宋体或仿宋、小四，行距 1.5 倍或固定 28 磅。
- 对外邀请函留足够页边，署名在右下方或居中，不和议程表挤在同一行。
- 颜色克制：标题一种深色，表格表头浅底。不放难以印刷的底纹满页。
- 不放假印章、不写「已发送」。

## 自检

- 时间、地点、事项三项要么来自用户，要么标了待补充。
- 没有出现样例年会的酒店、流程和致辞人。
- 没有把未发生的会写成已经做出的决定。
- 称呼和落款的单位一致。
- `validate` 已通过。`office_render` 检查标题没有贴边、议程表没有溢出、时间列没有折成无法阅读的宽度。

## 常见错误

- 把会议纪要的「形成决议」写进邀请函。
- 议程时间重叠。
- 对外信函用内部黑话，或内部通知写成请柬体。
- 回复截止日期晚于活动当天还不标明。

## 文件交付

先 `officecli load_skill word`。不要用 Python 或 LibreOffice。样例只读，只学「称呼、时间地点、议程表、回复方式」的顺序。交付前走版式守卫。
