# 英文商务信函

用户要英文商业信函、合作邀约或正式英文函时用本技能。成品是 Word，正文是英文。说明和待补充提示可以用中文写在交付说明里，不写进信的正文。求职信走简历技能，不使用本技能的合作邀约结构。公文的函走公文技能。

## 信的顺序

1. 发信人姓名、职务、机构、地址、邮箱。缺的标 “To be confirmed”，不要编一个伦敦地址。
2. 日期。全篇只用一种写法，例如 1 November 2026。不要中英文日期各写一遍。
3. 收信人姓名、职务、机构、地址。不知道姓名时写职务，例如 Hiring Manager 不适合商务合作；合作函写 “Dear Sir or Madam” 仅在用户同意不知道姓名时使用，并在说明里标待补充。
4. 称呼后加逗号或冒号，全篇一致。正式场合用姓：Dear Ms Chen。不知道性别就用全名：Dear Chen Lin。
5. 第一段说明来意。
6. 中间段写用户给出的事实：合作什么、时间、需要对方做什么。没有的事实不写具体数字。
7. 结尾段写下一步，例如请于某日前回复。日期没有就不要写 “by Friday”。
8. 结尾敬语与称呼匹配。Dear Ms Chen 配 Yours sincerely；不知道姓名时用 Yours faithfully。不要用 Cheers，除非用户要求非正式。
9. 署名、职务。附件在署名下写 Enclosure，并列出用户提供的附件名。

## 语气

默认正式、短句、主动语态。不写俚语，不写夸张的赞美。用户要求中性或友好时，可以缩短敬语，但仍保留日期、称呼和署名。一封信只办一件事。

金额、日期、专有名词以用户原文为准。用户给的是中文机构名时，英文名未知就写中文名并标 “English name to be confirmed”，不要音译一个法定名称。

## 版式

- A4，上下左右约 2.54 厘米。英文用 Calibri 或 Times New Roman，11 或 12 磅，单倍或 1.15 倍行距。
- 每段之间空一行，段首不缩进。这是现代商业信的常见排法；用户要求传统缩进时再改，两种不要混用。
- 不居中整封信。标题只在用户要求时加一行事由，用 Re: 放在称呼之前。
- 不用彩色底纹和假签名图片。

## 自检

- 称呼、结尾敬语和是否知道收信人姓名，三者一致。
- 信里的日期、金额、机构都能回到用户材料。样例里的公司和合作内容没有残留。
- 没有求职经历，没有公文的「特此函达」。
- 待确认的姓名和地址没有被编造成具体街道。
- `validate` 已通过。`office_render` 看日期、称呼、署名是否各成一段，有没有中文待补充漏进英文正文。

## 常见错误

- 把合作邀约写成求职信，或把公文函译成 “This is to notify”。
- Sincerely 和 Faithfully 用反。
- 正文里夹中文「待补充」。英文正文用 “To be confirmed”，中文清单放在文件外的说明。
- 为了显得礼貌堆砌 very、kindly 和长从句。一句一个请求。

## 文件交付

先 `officecli load_skill word`。不要用 Python 或 LibreOffice。样例只读，只学信头、日期、称呼、分段和结尾的位置。交付前走版式守卫。
