# 发票与对账单

用户要对账、核对应付应收、或整理供应商月度对账单时用本技能。成品是 Excel。本表帮助把用户已经提供的发票和付款对齐，不开发票，不报税，不判断某张发票能否抵扣。

## 一行一笔

每行是一张发票或一笔付款，不要把一个月揉成一个手工合计数。建议列：

1. 对方名称
2. 日期
3. 发票号码或付款单号。没有就标待补充，不要编票号。
4. 币种
5. 不含税金额、税额、价税合计。用户只给了价税合计时，税额列标待补充，不要用 13% 倒推。
6. 已付或已收
7. 差异 = 价税合计 − 已付（或应收 − 已收，方向在表头写明）

合计用 SUM。期末余额 = 期初 + 本期发生 − 本期结算。期初用户没给就标待补充，不要假设为 0，除非用户说「从零开始」。

差异不为 0 的格子用条件格式标出。等于 0 的不涂色。不要用文字「异常」代替数字。

## 先问清的口径

- 这是我方应收还是应付。方向反了，差异的正负就反了。
- 币种是否统一。有外币时分列，不把美元和人民币加进同一个 SUM。汇率只在用户给了数字时使用，并注明日期。
- 对账期间的起止日。
- 发票金额是含税还是不含税。

## 版式

- 标题含对方名称和期间，例如「供应商月度对账单」。名称未知就写「待补充：对方名称」。
- 表头深色白字，差异列单独一列，数字右对齐、两位小数。
- 列宽够显示发票号，不能出现 `###`。
- 打印横向、宽度一页。冻结表头。
- 不嵌发票图片，除非用户要求并提供了文件。本技能不识别票面。

## 自检

- 抽两行：价税合计减已付等于差异。合计等于各行之和。
- 改一笔已付，差异和期末跟着变。`xlsx_recalculate` 后读回，缓存过期不能交付。
- 样例的供应商、票号、金额没有残留。
- 没有「可以抵扣」「税率一定是 13%」。
- 有条件格式或打印设置时用 `office_render` 看差异是否真的被标出。只改一个金额且格式未动，说明里写未截图。

## 常见错误

- 把未付款和已付款加在一起再减一次。
- 税额从价税合计里拆出来后又加回去，合计翻倍。
- 一张发票跨月，被两个月各记一次。按用户指定的归属月只记一次，另一月用备注说明。
- 用 Word 表格做对账，公式无法重算。

## 文件交付

先 `officecli load_skill excel`。不要用 Python 或 LibreOffice。样例只读。交付前重算，并核对差异合计与期末。
