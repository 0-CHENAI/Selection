# 项目计划、甘特与排班

用户要项目计划、甘特图或排班表时用本技能。成品是 Excel。这是进度和班次的表，不是项目管理软件，不算关键路径的概率，也不代替排班制度。

## 计划表的列

1. 任务或班次名称
2. 负责人。没有就标待补充，不要写「待定同事」。
3. 开始日
4. 工期（天或班）。工期是输入。
5. 结束日 = 开始日 + 工期 − 1。用公式，不要手填结束日。
6. 前置任务。没有就空着。前置的结束日晚于本任务开始日时，用公式标「日期冲突」，不要静默改日期。

甘特区按周或按日展开。某一格是否落在任务区间内，用公式判断（开始日到结束日覆盖该列），再用数据条或浅色填充显示。不要把「有任务」写成手工的 1，否则改工期后条形不跟着走。

排班表同样：行是人，列是日期，班次用输入，工时合计用 COUNT 或 SUM。不要把示例里的人名留下来。

## 先问清

- 项目或班表的起止。用户说「三个月」就要问从哪一天起，没说就从用户指定的月份 1 日，并在标题注明。
- 工期按自然日还是工作日。没说就按自然日，并在表头写明。不自行跳过周末，除非用户要求。
- 依赖关系。没给就不要编「必须先做完 A」。

## 版式

- 横向、宽度一页、高度可分页。重复打印标题行。
- 左侧任务列冻结。日期列宽一致，避免 `###`。
- 周末列用浅灰，仅当按自然日且用户要区分周末。
- 标题写项目名称和期间。名称未知标待补充。
- 颜色只表示「在区间内」或「冲突」，不用彩虹区分每一个任务，除非任务少于六项且用户要求图例。

## 自检

- 把某一行工期加 2，结束日和甘特条同时变长。
- 结束日公式没有被写成死日期。
- `xlsx_recalculate` 后读回至少一个结束日，与开始加工期减一一致。
- 样例的任务名、人员和日期没有残留。
- 有甘特条、条件格式或打印设置时用 `office_render` 看条形有没有断列、有没有盖住文字。只改一个任务名可以不截图，并写明。

## 常见错误

- 结束日 = 开始日 + 工期，多算一天。约定要写在列标题。
- 甘特用合并单元格画条，一改日期就错位。用按列公式。
- 排班把同一个人同一天排了两班还不提示。用公式数当天班次数，大于 1 时标出。
- 把产品需求文档的里程碑段落贴进表里充任务。里程碑可以是工期为 1 的行，但范围说明仍属于需求文档。

## 文件交付

先 `officecli load_skill excel`。不要用 Python 或 LibreOffice。样例只读。交付前重算，并核对结束日和至少一条甘特覆盖公式。
