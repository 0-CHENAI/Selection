# 版式

按论证关系选版式，不把所有信息放进同一种卡片。相邻页的 `layout` 不能相同。每套风格的具体坐标在它的 `deck.json` 里，这里只规定该用哪一种。

| layout | 页面在论证里的作用 |
|---|---|
| `cover` | 一个主张，一个主数字，一个下一步。两套风格的封面构图不同 |
| `conclusion` | 结论先出现，证据是少量大数字 |
| `trend` | 一条序列，旁边写波峰或回升的读法 |
| `evidence-tree` | 一个判断连到几条互相独立的证据 |
| `matrix` | 两个维度，只突出应该先做的那一格 |
| `waterfall` | 起点、变化、终点。起点加变化必须等于终点 |
| `scorecard` | 指标、实际、目标、行动。偏离的行和保持的行要能分开 |
| `gantt` | 时间顺序和一道闸门。闸门后的决定不要画到闸门前面 |
| `case` | 两个对象的同一组指标 |
| `architecture` | 交接或依赖。连线必须对得上句子里的那一段 |
| `funnel` | 同一队列的各段数量。封面如果引用了其中一段，这里要能对上 |
| `closing` | 一个问题，一项或两项行动 |

一页只有一个主张。图表类别使用用户材料里的原词，单位写在标题、轴旁或来源里。瀑布图中间项是变化量，首尾是总量。

内容页沿用该风格参考页的页眉、页脚线、来源和页码。来源写这页数字从哪来；示例页的「示例 · 非真实…」不能留在正式稿里。
