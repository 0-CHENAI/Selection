# 版式

每套风格的 `layout` 写在它自己的 `deck.json` 里，形如 `01-cover`、`02-content`。这些 id 只用来区分相邻页，不是各套共用的版式名。具体坐标、页眉和页脚以锁定风格的参考页为准，不要套用另一套的网格。

结构版式在 [layouts/catalog.json](../layouts/catalog.json)。七套来自 ppt-master 的 SVG 页面，颜色是 token，默认主题是中性石板色。画布分别是 16:9、4:3、1:1、9:16 和 3:4。选用某一套时，deck 的 `canvas` 用该套的尺寸，不要把竖版页面硬塞进 960×540。图片位是虚线框，渐变已铺平。

相邻页的 `layout` 不能相同。一页只有一个主张。

## 论证版式库

上面的结构版式决定画布。论证版式是另一套可复用的 960×540 页面，引擎可以直接调用，`deck_check` 会按目录里的 `bounds` 和 `textCapacity` 识别。`layout` 必须是下表的 id。槽位元素的类型、坐标要和目录一致（容差 0.5 pt），文字的 `textCapacity` 不能大于目录。换文字时保留目录容量。未知的 `layout`（例如 `01-cover`）仍然合法，不会被当成论证版式。

目录：

```text
"$CRAFT_BUN" "<skill>/engine/deck-cli.mjs" layouts
```

| id | 页面 | 论证关系 |
|---|---|---|
| `conclusion` | 结论页 | 判断占左半页，右边三个证据 |
| `evidence-tree` | 证据树 | 一个判断连到三条互相独立的证据 |
| `matrix-2x2` | 矩阵 | 两个维度，只强调先做的那一格 |
| `waterfall` | 瀑布图 | 起点加变化等于终点 |
| `trend-annotated` | 趋势加标注 | 一条序列，标出回落和高点 |
| `scorecard` | 计分表 | 指标、当前值、条形和偏离 |
| `gantt-roadmap` | 甘特路线图 | 工作按季度铺开 |
| `architecture` | 架构 | 用户、渠道、中台、底座 |
| `case-compare` | 案例对比 | 同一组指标的现状和目标 |
| `funnel` | 漏斗 | 四段收窄，点出最大流失 |
| `process` | 流程 | 五步顺序和底部交接 |
| `timeline` | 时间线 | 四个时点 |
| `closing` | 收束 | 一个问题，一项本周行动 |
| `decision` | 取舍 | 建议和这次不做的事 |

示例页里的数字只说明几何。正式稿换成用户材料，来源写这页数字从哪来。图表类别使用用户材料里的原词，单位写在标题、轴旁或来源里。内容页沿用锁定风格的颜色和字体；论证版式只规定槽位，不代替 `design.md`。
